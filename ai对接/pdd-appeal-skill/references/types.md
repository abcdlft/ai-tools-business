# 申诉类型地图

入口：`https://mms.pinduoduo.com/orders/appeals/aftersale/order?from=list`（订单申诉列表）。
**页面结构与文案以当天实际页面为准**；对不上就停下向用户确认，不猜、不套模板。

## 实测页面结构（2026-11-16）

列表页 DOM 快照里能直接读到的：

- 页签文本（一行）：`维权申诉(14) 订单赔偿申诉(3) 极速退款申诉(40) 极速换货申诉(2)`
- 每行订单号，例如 `<a node_id=59>ORD-XXXX-XXXXXX</a>`
- 每行三个动作节点：「发起申诉」「售后详情」「暂不申诉」

快照里**读不到**：商品规格、退款金额、退款时间、申诉倒计时。这些只在详情页。

### 维权申诉弹窗（2026-11-16 实测，列表页直接点「发起申诉」打开）

在列表页点该行「发起申诉」即可在**当前页**弹出「维权申诉」表单，不用先开详情页。

| 字段 | 是否自动 | 说明 |
|---|---|---|
| 申诉订单号 | 自动带入 | 只读，核对 |
| 申诉项 | 自动带入 | 如「货款申诉」 |
| 申诉原因 * | **必选下拉** | 见下方选项清单 |
| 申诉金额 * | 需填 | 旁边显示「最高可申诉 X.XX 元」，等于该单退款金额 |
| 申诉描述 | **选完原因后可能消失** | 表单随申诉原因动态变化：选中后可能出现「必填凭证」区，描述框消失 |
| 必填凭证 * | 至少 1 份 | 文案「请至少上传1份有效凭证，无凭证会影响申诉结果」；要求项随原因变化，例如「两单物流轨迹（需明确是哪个平台的包裹，以及提供问题的对应链接）」 |
| 选填凭证 | 可不传 | 「其他证明购物凭证的有效凭证」 |
| 按钮 | — | 提交申诉 / 取消 |

**申诉原因下拉实测选项**（顺序按页面，共 6 项可见，列表可滚动）：

1. 消费者反馈未收到商品，但实际已签收
2. 消费者反馈空包或少件，但实际未少发
3. 消费者反馈商品破损，但实际未破损
4. 消费者反馈商品存在质量问题，但无凭证
5. 消费者反馈商品为假货，但实际为正品
6. 投诉订单消费者不合理行为

> 下拉 item 文字以选中后框内回显为准，**选完必须回读确认**，不要凭序号假设。

### 交互方式（重要）

- 下拉框**不能用 dom_cua_click 展开**（Ant Select 监听 mousedown，程序化 click 无效）。
- 可行路径：先 `focus <tab>` 把窗口拉到前台，再用 `tap <tab> --at x,y` 坐标点开；坐标点不开就先 focus。
- 列表页的「发起申诉」按钮用**文本模式** `click <tab> "发起申诉#1"` 最稳，node_id 模式常失配。
- 详情页主体在 iframe，DOM 只有顶部导航，**任何按钮都只能截图 + 坐标点**。

操作路径：

```
列表 → 点「发起申诉」→ 打开该单「售后详情」页（新标签，标题仍是"拼多多 商家后台"）
     → 详情页状态区有「极速退款申诉」按钮 → 点开申诉表单弹窗
```

详情页可读内容（iframe 内，必须截图看）：

| 字段 | 示例 |
|---|---|
| 售后编号 / 售后类型 | ID-XXXX / 【极速退款】 |
| 退款金额 / 退款件数 | ¥99.5（退款2件）、实收 ¥199.51 |
| 申请原因 / 申请说明 | 【不喜欢】/【不喜欢】 |
| 订单编号 / 成交时间 | ORD-XXXX-XXXXXX / 2026-10-25 10:04:26 |
| 是否包运费 | 已补偿（运费金 12.05 元） |
| 商品与件数 | 【全芯升级】…全包臀拉拉裤3XL码一箱2大包80片，共 2 件商品 |
| 售后状态 / 剩余申诉时间 | 已极速退款成功 / 「超过 12 天 12:10:38 申诉入口关闭」 |
| 协商详情 | 退款成功 2026-10-30 08:31:27 |

申诉表单弹窗（「极速退款申诉」）结构：

## 1. 运费申诉（退货运费）

- **优先原因：`退货运费 / 消费者无理由退货，退货运费不应商家承担`；事实不符时可选「其他 / 非以上申诉原因」并在描述写清。** 禁止的只有带「商品有问题」字样的选项（全类型通用铁律）。
- **入口：就在「维权申诉」页签里，没有独立的「运费申诉」页签**（用户 2026-11-16 确认）。列表页四个页签：维权申诉 / 订单赔偿申诉 / 极速退款申诉 / 极速换货申诉。运费单和货款单都落在「维权申诉」，靠每行的「申诉项」列区分。
- 本店当前（2026-11-16）维权申诉 14 单，**申诉项全部是「货款申诉」，没有运费单**。是否跑运费申诉要看「申诉项」列有没有「运费申诉」。
- 只处理运费，不处理货款；同一订单可能同时有货款和运费两条申诉，分开提。
- 典型情形与对应话术（`reply-library.json` 里 `appealType = 运费`）：
  | 情形 | 话术 id | 必附凭证 |
  |---|---|---|
  | 个人无理由退货（自述不喜欢/不合适） | prod-freight-1 | 商品完好图、聊天 |
  | 仅模糊照片被判质量赔付 | prod-freight-2 | 质检报告、实拍对比 |
  | 买家寄到付 | prod-freight-3 | 到付面单、未承诺到付的聊天 |
  | 少件退货仍全额退+全额赔运费 | prod-freight-4 | 发出/退回称重、拆包视频 |
  | 单号异常、物流停滞 | prod-freight-5 | 物流停滞截图 |
  | 已支持7天无理由还要运费 | prod-freight-6 | 聊天 |
  | 运费险已赔又扣一次 | prod-freight-7 | 订单、理赔记录 |
  | 换货改地址/私自拒收 | prod-freight-8 | 订单、聊天 |
  | 兜底 | prod-freight-9 | 订单、聊天 |

## 2. 货款申诉 / 仅退款（货值损失）

- 争议对象是「不该退的钱 / 不该判的仅退款」，不是运费。
- 常见固定原因：商品无质量问题、未协商同意仅退款、退货少件、虚假退货、描述不符被判错误。
- 情形与话术（`appealType = 货款/仅退款`）：
  | 情形 | 话术 id |
  |---|---|
  | 过敏-纸尿裤（红疹 / 图片只有患处无产品同框） | prod-allergy-1、prod-allergy-2 |
  | 过敏-安心裤（无医院诊断 / 有公立医院诊断） | prod-allergy-5、prod-allergy-6 |
  | 漏尿-纸尿裤 | prod-leak-1 |
  | 漏液-安心裤（仅口头 / 有照片无缺陷 / 超吸收量） | prod-leak-3、prod-leak-4、prod-leak-2 |
  | 高分子漏出（亮晶晶颗粒） | prod-sap-1 |
  | 掉毛/浮毛 | prod-fluff-1 |
  | 零沟通直接仅退款 | prod-norefund-1 |
  | 退货少件 | prod-returnless-1 |
  | 外包装印刷尺码≠链接尺码 | prod-sizelabel-1 |
  | 易破/一扯就破 | prod-easytear-1 |
  | 尺码偏小/批次差异 | prod-sizesmall-1 |
  | 片数少 | prod-pieceshort-1 |
  | 虚假退货（物流只揽收） | prod-fakeret-1 |
- 平台历史话术（`id` 以 `platform-` 开头，`scene` 为空）共 56 条，是历年货款补款申诉的实际用语，用于换语气、补句式，不要整段照抄平台腔。

## 3. 负向体验 3 元扣款

- 单笔金额小、量大，判定重点在「有没有服务违规」而不是「商品有没有问题」。
- 话术：`appealType = 负向体验3元`，5 条（无凭证 / 已给退货方案 / 已和解 / 肤质差异 / 兜底）。
- 关键事实：客服响应及时、主动给方案、未见辱骂或拒不处理。买家无凭证时主打「无有效凭证 + 无服务违规」。

**当前统一口径（2026-11-18 SHOP-XXXX店用户确定，优先于上面的分型话术）**：
- 所有负向 3 元申诉话术统一走「**已妥善处理售后退款 + 商品质检合格 + 无服务违规，恳请撤销扣款**」这一条主线，不再按反馈类型分型写。
- 理由：本类扣款是平台在商家已退款后额外收取的体验补偿，商家已完成退款即已履行售后义务；商品有合格检测报告即可证明质量合规。
- 原因下拉仍选「其他」；描述正文按上述主线写（正文里避免写「其他申诉原因」字样）。
- **检测报告必须品牌+品类双匹配**：SHOP-XXXX店商品标题写「TUTUBABY山茶花 / TUTUbaby正品山茶系列」，实际产品是**山茶花兔小贝**，报告用 `A 山茶花 兔小贝`（拉拉裤用「拉拉裤.jpg」、纸尿裤用「纸尿裤.jpg」，样品名称「兔小贝山茶花婴儿学步裤/纸尿裤」、委托单位福建省百顺）。**禁止**用 `A TUTUBABY 蚕丝精灵` 报告——那是另一条产品线（2026-11-18 踩坑：23 单曾全部错传蚕丝精灵报告）。映射已修正见 `report-map.json`。

## 4. 违规处罚 / 服务违规申诉

- 典型：虚假发货、物流异常未反馈、承诺未履行、评价违规。
- 话术：`prod-promise-1`（承诺跟进事项的留证，防「未如实反馈」判罚）。
- 关键事实：承诺过的事项是否已告知、留证是否完整、是否在时限内反馈。

## 5. 不在范围内

货款申诉与运费申诉不要混在一个 decision 里；评价举报、商品下架申诉走各自入口，不要套用运费原因。
