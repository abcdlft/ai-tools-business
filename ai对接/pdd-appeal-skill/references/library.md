# 话术库用法

`references/reply-library.json` 共 91 条，两个来源合并：

- `id` 以 `platform-` 开头（56 条）：历年货款补款申诉的实际用语，`scene` 为空。用来借语气、补句式，**不要整段照抄**，平台腔太重。
- `id` 以 `prod-` 开头（35 条）：本店产品话术，带 `scene`（情形）和 `evidence`（必附凭证），覆盖运费、货款、负向 3 元、舆情说明、服务违规。

## 检索顺序

1. 先按 `appealType` 缩小：`运费` / `货款/仅退款` / `负向体验3元` / `舆情/说明` / `服务违规`。
2. 再按 `scene` 里的关键词匹配本单事实：`过敏`、`漏尿`、`漏液`、`高分子`、`掉毛`、`少件`、`片数`、`尺码`、`易破`、`到付`、`碎片`、`停滞`、`运费险`、`拒收`、`无沟通`。
3. 找到后**按本单实际替换**：金额、包数、片数、尺码、单号、时间。
4. 没有贴合的条目时，按最近那条的语气结构自己写，不要硬套不成立的事实。

## 改写规则

- 事实只能来自本单证据；库里的话术是句式模板，不是事实来源。
- 保留「事实 → 依据 → 诉求」三段结构：先说本单发生了什么，再说规则/质检/凭证支持什么，最后说请求平台做什么（撤销扣款 / 返还运费 / 驳回退款 / 复核）。
- 一条写 80–200 字最稳；平台输入框上限通常够，但**不要塞三个诉求**。
- 多情形叠加时（例如过敏 + 无凭证 + 已给退货方案），取主线，其余作为补充句，不要罗列。
- 段落编号 `①②③` 只在内容确实分点时用，平台审核员阅读时更清楚。

## 写作禁忌

1. **不写「其他」**：出现「其他申诉原因」相关字样会连累原因选择，正文也避开。
2. 不写「买家恶意」「买家讹诈」这类定性 —— 只写行为事实（未沟通、未提供凭证、私自到付）。
3. 不写「一定能通过」「保证退款」。
4. 不写没有依据的标准号、机构名、检测结论；要么有报告在手，要么不写。
5. 不把「我们已同意退货退款」写成「买家已认可」——除非聊天里确有认可。

## 常用替换对照

| 占位 | 换成 |
|---|---|

| `2 包 / 1 包` | 本单实际购买与退回数量 |
| `XXXXXXXXXXXXXX` | 买家退货物流单号 |
| `3 元` | 负向扣款实际金额 |
