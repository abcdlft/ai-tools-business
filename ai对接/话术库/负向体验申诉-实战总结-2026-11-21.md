# 负向体验申诉 · 实战总结（2026-11-21）

> 负向体验 = 平台以"消费者体验不好"为由，从商家账上扣 3 元补偿买家。**它和仅退款申诉是两套完全不同的东西**，不要混用话术。
> 数据：本店近 90 天 14 条负向体验记录（7 条申诉通过、6 条申诉未通过已处罚、1 条可申诉），原始数据见 `申诉案例库-2026-11-21.json` 的 `negative` 段。

---

## 一、先分清：负向体验 ≠ 仅退款

| 对比项 | 负向体验申诉 | 仅退款申诉（货款） |
|---|---|---|
| 扣的钱 | 3 元体验补偿（固定） | 商品货款（几十元） |
| 触发原因 | 平台判断"商品/服务让消费者体验受损" | 买家申请退款/退货退款 |
| 入口 | `mms.pinduoduo.com/aftersales/customer_complain_appeal` | 订单申诉 → 维权申诉 / 极速退款申诉 |
| 关键证据 | 聊天记录（买家有没有沟通）、售后协商详情 | 退款申请单 + 备注 + 聊天 + 报告/称重 |
| 申诉理由选项 | 下拉（实测多为"其他"） | 下拉（质量问题凭证不足 / 少退商品 …） |
| 成功后 | 违规处理取消，3 元退回 | 返还货款 |
| 本店成功率 | XX/XX ≈ XX% | 全退 XX%、部分退 XX% |

**最容易犯的错**：把仅退款那套"质量合格/检测报告"话术照搬到负向体验，平台不认——负向体验考的是"消费者体验是否受损"，不是"产品是否合格"。

## 二、入口与操作（2026-11-21 实测）

1. 打开 `https://mms.pinduoduo.com/aftersales/customer_complain_appeal`
   （注意：`/orders/appeals/negativeExperience` 是无参数的单条空表单，不是列表页）
2. 页面顶部统计条：`可申诉次数 不限（N 单 **查看可申诉订单**）`、`可申诉订单数`、`近30天申诉成功数`、`近30天申诉成功金额`
3. **点"查看可申诉订单"**：列表立刻只剩当前可申诉的（本店 14 条 → 1 条），避免在"申诉未通过已处罚"的行里逐个试
4. Tab：全部 / 商品问题 / 服务问题；列表列：订单编号、商品信息、问题类型、补偿金额（3）、扣款进度、创建时间、处理状态
5. 行内「查看详情」→ 新标签页 `detail?ticketSn=...`，含平台自动生成的"补偿原因"（基于聊天记录与售后协商详情总结）

> 提示：如果只想批量取数，直接页面内调接口更快：
> `POST /api/colombo/tuju/appealList` 拿列表（含 ticketSn、appealStatus：1 可申诉 / 4 驳回 / 5 通过）；
> `POST /api/colombo/tuju/detail` ＋ `{ticketSn}` 拿详情（含 `appealDetail.appealNote` 商家原文、`appealEvidenceImages`）。

## 三、成功 vs 失败：原话术对比（最有价值的部分）

### 失败的三种写法

**写法 1（3 条完全相同的文案，全部失败）**
> 产品没有问题，消费者误解，客服耐心和消费者沟通解释后，消费者无再反馈问题与申请售后，希望平台审核清楚，还给我们一个清白，恳请撤销处罚

失败原因：全是商家主观判断（"产品没问题""消费者误解"），没有任何可核查的事实，也没有证据指向"体验未受损"。平台看到的是"商家在辩解"。

**写法 2（承认了瑕疵，等于送分）**
> 买家也没有向我们提供任何的质量问题的照片和凭证，商品都是有质检报告的……我们的尿不湿都是近期生产的，生产日期越新的产品越可能有原材料和高温消毒的味道，味道没来得及完全散发，对宝宝使用完全没有影响……

失败原因：前半段在说"无凭证"，后半段却自己解释"为什么有味道"——等于承认商品有异味，坐实了"体验受损"。

**写法 3（只传 1 张无关截图）**
> 失败案例里 5 条只上传了 1 张凭证，且多为订单截图，无法证明"买家未沟通"。

### 成功的写法

**成功样本 1（ORD-XXXX-XXXXXX）**
> 尊敬的平台审核专员：您好，买家未提前通过订单聊天窗口与我方进行任何沟通协商，全程没有主动向商家说明问题细节、描述使用情况，也未提供任何实拍照片、视频等有效问题凭证，无法证实商品存在质量问题，恳请平台审核清楚，还小店一个清白！

**成功样本 2（ORD-XXXX-XXXXXX）**
> 亲亲不喜欢 7 天可以无条件进行退货退款哦，需要我帮您申请一下售后吗
> （这是把**客服主动给解决方案的聊天记录**当凭证提交，证明商家已尽责）

### 结论（写成规则）

| 写这些 | 结果 |
|---|---|
| "买家全程未在聊天窗口沟通 / 未提供任何照片视频" | ✅ 有效（可核查的事实） |
| "客服已主动给出退货退款/补发方案，买家未回应" | ✅ 有效（证明商家尽责） |
| "产品没有问题""消费者误解""还我们清白" | ❌ 无效（主观辩解） |
| 解释"为什么会有味道/为什么漏尿" | ❌ 反而坐实问题 |

**一句话**：负向体验申诉打的是"**买家没沟通、没举证、商家已尽责**"，不是"产品合格"。

## 四、负向申诉话术模板（可直接用）

### 模板 A：买家零沟通零举证（首选，成功率最高）

> 尊敬的平台审核专员：您好，本单买家自下单至售后结束，未通过订单聊天窗口与我方进行任何沟通协商，未说明使用情况、未描述具体问题，也未提供任何实拍照片或视频凭证。我方在收到售后申请后第一时间主动联系买家并给出退货退款方案，买家未回应。在无任何有效举证的情况下判定商品体验问题，缺乏事实依据，恳请平台复核并撤销本次补偿扣款，谢谢。

### 模板 B：商家已尽责（有聊天记录时用）

> 本单买家反馈问题后，我方客服已第一时间响应，主动提出退货退款/补发方案（见聊天记录截图），并告知支持拆包试用 5 片、不合适可退。买家未继续沟通、未提供问题凭证，售后已按平台规则处理完毕。商家已尽到告知与解决义务，本次体验补偿缺乏依据，恳请平台复核撤销。

### 模板 C：买家已在别处获得补偿（有退货退款记录时用）

> 本单买家已就同一问题申请退货退款，平台已完成退款，货款问题已解决。买家未额外提供任何体验受损的凭证，商家也已承担退货运费损失。再次以体验为由扣款 3 元，属重复补偿，恳请平台核验售后记录后撤销本次扣款。

> 凭证建议：**聊天记录截图（含时间、完整对话）** + **售后协商详情** + **订单/物流凭证**。不要传检测报告（负向场景不认这个，反而显得答非所问）。

## 五、处理节奏

1. 每天早上看一次"可申诉订单"，剩余时间过期就没了（列表会显示"剩余 N 天 N 时"）。
2. 可申诉里优先做：**买家零沟通**的（模板 A）；**有退货退款记录**的（模板 C）。
3. 买家在聊天里发过清晰问题照片的，**不要申**（必败），让它扣 3 元更省事。
4. 已"申诉未通过已处罚"的不能再提，别重复操作。

## 六、2026-11-22 实战补充（5 单全部提交成功）

### 6.1 原因选项以页面为准，接口字段会误导

接口 `detail.supportedAppealReason` 返回 6 项（已安抚并补偿过消费者 / 已解决问题不应额外补偿 / 补偿金额过高 / 消费者所述问题经核验不存在 / 消费者误解商品信息 / 消费者未表达商品问题），
但**页面下拉只有 5 项**：

1. 商品无问题，消费者误解
2. 商品有问题，但已与消费者达成一致其他售后方案
3. 商品有问题，但消费者主动表示无需处理
4. 消费者未表达商品问题（含售后详情内未描述问题等）
5. 其他

> 按接口文案去选会直接失败（脚本报「未找到选项」）。**永远先 dump 页面 li 选项再选。**

### 6.2 平台已预设反驳「已处理售后」

负向详情 `merchantQuestionAnswerVOS` 里平台自己的回答：
> 「虽然您已经处理了售后，但消费者在购物过程中遇到了不便，带来体验损失……这笔负向体验补偿金，就是为了抚平这些无形的、非物质损失。」

所以「已退货退款、不应再补偿」这条路平台是**认账但不认同**的；申诉重心放在「买家未举证 / 未表达具体问题」更容易过。

### 6.3 本批 5 单的写法对照

| 场景 | 用哪个原因 | 关键句 |
|---|---|---|
| 买家只在聊天里口头说漏尿/红屁股，零照片 | 商品有问题，但已与消费者达成一致其他售后方案 | 客服第一时间致歉并主动申请退货退款（享退货包运费），买家已同意，售后闭环 |
| 原因选「不想要了」、说明仅 4 字、零聊天零图 | 消费者未表达商品问题 | 个人原因退货 + 聊天仅系统签收消息 + 未上传任何照片 |
| 说明只有一句「漏尿」，聊天只有系统消息 | 商品有问题，但已与消费者达成一致其他售后方案 | 收到退货即同意退款 + 聊天图片字段为「-」 |
| 说明为空、只发过一张外包装照片 | 消费者未表达商品问题 | 唯一图片是外包装正面（可见规格），未展示漏液/破损/异常 |
| 选「质量问题·漏尿」但零图零聊天 | 消费者未表达商品问题 | 仅一句描述，无使用情况、无照片，「暂无售后聊天记录」 |

### 6.4 操作坑

- 负向表单可直达：`/orders/appeals/negativeExperience?orderSn=&ticketSn=`，不必从列表点。
- 原因下拉是 beast-core Select，**坐标点击不生效**；要对 `IPT_outerWrapper` 派发 `mousedown/mouseup/click` 才展开。
- 连续提交 4 单后触发**旋转拼图安全验证**：关闭弹窗（右上角 X）后等待约 10 分钟再提，可正常通过。
- 负向申诉**不要传检测报告**；凭证用「退款申请单（含聊天图片字段为 -）+ 聊天记录」两张即可。
