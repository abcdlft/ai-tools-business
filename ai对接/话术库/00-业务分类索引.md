# 00 · 业务分类索引（AI 对接第一步先看这里）

> 每次接新任务，**先判断属于哪一类业务，再打开对应的规则/话术文件**，不要一上来就翻所有资料。
> 更新时间：2026-11-21（本版基于本店近 90 天 144 条申诉记录 + 14 条负向体验记录实测整理）

## 一、一句话分流

| 你看到的情况 | 属于 | 先读哪个文件 |
|---|---|---|
| 买家申请退款/退货退款，平台已退款或待处理，商家想把钱要回来 | **仅退款申诉（货款申诉）** | `仅退款申诉话术思路参考.md` |
| 平台已介入直接退款（列表里搜不到这单），商家事后追货款 | **平台介入退款 → 货款申诉** | `仅退款申诉话术思路参考.md` **场景 F** |
| 买家退货，平台把退货包运费从商家账上扣了，商家想追回运费 | **运费申诉** | `运费申诉话术库-2026-11-19.md` |
| 平台因"消费者体验不好"从商家扣 3 元补偿给买家 | **负向体验申诉** | `负向体验申诉-实战总结-2026-11-21.md` |
| 平台额外判了赔付单/扣款（非货款、非运费） | **赔付单申诉** | 本文件第四节 + `仅退款申诉话术思路参考.md` 第五节 |
| 买家反复仅退款导致"纠纷退款率"变红，影响店铺 | **纠纷退款率申诉** | 本文件第四节 |
| 三要素对得上，这单不值得申诉 | **暂不申诉** | `暂不申诉判定与总结.md` |

## 二、四类申诉不能混（这是最容易犯的错）

| 维度 | 仅退款（货款申诉） | 运费申诉 | 负向体验申诉 | 赔付单申诉 |
|---|---|---|---|---|
| 页面入口 | 订单申诉 → 维权申诉 / 极速退款申诉 页签 | 同上，但申诉项显示"运费申诉" | `mms.pinduoduo.com/aftersales/customer_complain_appeal` | 订单申诉 → 订单赔偿申诉 页签 |
| 争议标的 | 商品货款 | 退货运费（0.1~6 元居多） | 3 元体验补偿扣款 | 平台额外赔付扣款（20~60 元） |
| 关键动作 | 发起申诉 → 选原因 → 传凭证 → 填金额 | 同左，金额必须 ≤ 弹窗"最多可申诉" | 查看可申诉订单 → 发起申诉 | 同货款 |
| 能不能点"暂不申诉" | 三要素对得上可以 | **绝对不行**（等于放弃运费） | 不适用（只有可申诉/已处罚） | 一般不用 |
| 成功率（本店实测） | 25% 全退、75% 部分退 | **100% 全退** | 约 50% | 80% |

> 判定顺序永远是：**先看列表"申诉项"列**，再决定走哪套话术。原因选项相似但标的完全不同。

## 三、页面操作要点（2026-11-21 实测，省时间用）

1. **每页条数可改**：申诉列表右下角"每页 10 条"→ 点开选 **50**，144 条只需翻 3 页（原来要 15 页）。
   选择器：`[class*=PGT_sizeSelect]` → 下拉里点 `50`。
2. **负向体验看全部可申诉单**：进负向体验页 → 顶部统计"可申诉次数 不限（N 单 **查看可申诉订单**）"→ 点它只筛出当前可申诉的，避免在"已处罚"行里浪费时间。
3. **负向体验列表页**：`/aftersales/customer_complain_appeal`（不是 `/orders/appeals/negativeExperience`，后者是无参数的单条空表单）。列：订单编号 / 商品信息 / 问题类型 / 补偿金额 / 扣款进度 / 创建时间 / 处理状态。
4. **金额填弹窗上限**，不是详情页金额。填多了直接被拦，填少了白亏。
5. **必填凭证与选填凭证是两套上传框**：运费弹窗 4 个 file input，顺序固定 = 0 必填图片 / 1 必填视频 / 2 选填图片 / 3 选填视频，**必须用第 0 个**。
6. **顶部全局搜索浮层会挡住表单**：先 `document.querySelector('[class*=mms-header_search_new]').style.display='none'`。
7. **提交成功弹窗有"继续申诉"**，真实坐标点击会打偏，用 JS 点击关闭。

## 四、赔付单 / 纠纷退款率：一句话要点

- **赔付单申诉**（申诉项"赔付单申诉"，原因常选"消费者举证商品问题凭证不足"或"退款后额外扣款"）：核心是"平台判赔缺乏事实依据"，话术三段——① 买家全程未沟通/未举证；② 商家出库有核验、有检测报告；③ 请求复核撤销扣款。本店 5 条中 4 条全退。
- **纠纷退款率申诉**（申诉项"纠纷退款率申诉"，无金额）：核心是"同一订单重复索赔"或"买家举证不足以归责"，要附完整退货核验证据（称重 + 开箱视频 + 面单）。本店 3 条全部成功。

## 六、铁律（踩过的坑）

1. 描述里**不要写检测报告没覆盖的指标**。山茶花/兔小贝报告只有微生物 6 项，写"渗透性能合格"会被驳回。
2. **不要自拟申诉原因**，只能用下拉里的选项；选不到就选"非以上申诉原因"（该选项成功率并不低）。
3. 敏感词会拦截提交：`不能用`、`无法正常使用`、`运费险`。改成"未达预期""运费补贴"等中性表述。
4. 同一 ticket 驳回后**不能二次提交**，只能走复议（复议也要凭证）。
5. 凭证宁少勿错：错配品牌报告比不传报告更糟。
6. **下拉选项一律以页面为准**：负向体验的接口原因字段（6 项）与页面实际选项（5 项）不一致，按接口文案找不到选项。选之前先 dump 页面的 li。
7. **维权申诉页若自动弹「批量申诉通道」，先关掉再点单行「发起申诉」**；运费弹窗的「最多可申诉」可能远小于「已补偿运费」，按上限填。
8. **凭证图片有硬上限：每个上传区最多 3 张图、2 个视频**（弹窗原文"图片最多3张，视频最多2个"）。**一次传 3 张正好传满；若该区已有图，再传的第 4 张会被组件直接丢弃**，表现就是"看着上传成功但数量不变"，`input.files.length` 也会被清零。所以：① 传之前先数该区的 `[class*=UPD_thumbnailItem]` 个数，别重复传；② 已满 3 张就是到位了，`background-image` 为 `blob:` 开头即本地预览已生成；③ 要换图必须先点缩略图上的 × 删掉再传。
9. **平台介入退款的单在申诉列表搜不到**，走「售后详情页 → 维权申诉」，弹窗申诉项即显示"货款申诉"，金额上限=已退款金额。详情页尽量复用同一标签页 `Page.navigate`，新开标签页更容易触发滑块验证。
10. **复议口径（11-22 四单全败换来）**：失败后复议，**绝不写"商品合格/无质量问题/同款统一规格"替商品背书**——平台看得到聊天记录，越背书越像回避消费者反馈。只主张「消费者未举证/举证不完善、现有材料无法核实」，配进货凭证+对应产品质检报告。详见 `仅退款申诉话术思路参考.md` 第九节。
11. **复议描述硬上限 300 字**，超了接口静默拒绝且前端无提示（返回 `errorCode:ID-XXXX`）；**必填凭证不填满会被前端拦截**，运费复议的凭证区是选完原因后才渲染的。
12. **列表"复议失败 复议权益"不是审核结果**，是"原始申诉失败+商家已发起复议"的状态标记；详情页顶部「申诉失败 / 商家发起复议」，复议结果以平台后续通知为准。
