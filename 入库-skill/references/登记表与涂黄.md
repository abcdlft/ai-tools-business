## 2. 列定义

| 列 | 字段 | 说明 |
|---|---|---|
| A (0) | 日期 | 日期型，`numFormat` 常为 `m"月"d"日"`，值是序列号（如 46346 = 2026-11-20） |
| B (1) | 单号 | 快递单号；也常出现拼多多**原订单号**（`465…` 15 位）、`母DPK…/子DPK…`（组套主从） |
| C (2) | 产品货号 | 如 `XZ-NB62`、`RS-L40`、`BBT-AX22M/L`（含 BBT 的要交人工） |
| D (3) | 完整数 | 可为空 = 0 |
| E (4) | 破·脏·次品数量 | 可为空 |
| F (5) | 备注 | **不要动**。历史值有「已确认入库」「原单号入库…」 |

**待入库 = F 列备注为空的行，且 A~E 未涂黄。**

## 3. 读取

```
sheet.get_range_data
file_id: <file_id>
range: { sheet_name: "Sheet1", rowFrom: <起>, rowTo: <止>, colFrom: 0, colTo: 6 }
```

`range` 必须是**对象**，字段 `rowFrom / rowTo / colFrom / colTo / sheet_name`，行列都从 0 开始。

> ⚠️ **行号换算：WPS 表格界面显示的行号 = API 的 `rowFrom` + 1**。用户报的行号是界面看到的（1 起），API 的 `rowFrom` 是 0 起。给用户汇报时用「用户行号 = rowFrom+1」，涂黄写 API 时用「rowFrom = 用户行号-1」。**混淆会导致涂到相邻行**——实测 2026-11-27：用户报 10540 行的单，API rowFrom 是 10539。

返回 `data.detail.rangeData` 是**单元格数组**（不是二维数组），每项带 `rowFrom/colFrom/cellText/cell_background_color/numFormat`。自己按行列聚合成行。

注意：**空单元格可能整条不返回**，所以缺列是正常的，按 0 / 空处理。

## 4. 涂黄

**唯一正确写法**（2026-11-22 实测）：

```
sheet.update_range_data
file_id: <file_id>
worksheet_id: 1
rangeData: [{
  opType: "format",
  rowFrom: 8408, rowTo: 8408,
  colFrom: 0, colTo: 4,
  xf: {
    type: 1,
    fill: {
      type: 1,                                          // ← 填充类型：1=实心
      back: { type: 2, value: 4294967040, tint: 0 },     // ← 颜色：2=ARGB，tint 必填
      fore: { type: 255, value: 0, tint: 0 }             // ← 255=自动色
    }
  }
}]
```

三个必踩的坑：

1. **`fill.type` 是「填充类型」，不是颜色类型**。写 `fill: {type:2, value:4294967040}` 等于「图案填充（斜纹）+ 忽略颜色」，单元格会变成**灰黄斜纹**，看起来像没涂干净。必须 `fill.type: 1`（实心），颜色放进 `back`。
2. **颜色对象 `tint` 必填**。`back: {type:2, value:...}` 少了 `tint` 会报 `第三方服务错误：Internal error`，报错信息完全看不出是缺字段。
3. **颜色类型**：`0=ICV / 1=主题色 / 2=ARGB / 254=无颜色（清空填充用）/ 255=自动色`。黄色 ARGB `0xFFFFFF00` = `4294967040`。

清空填充：`fill: {type:1, back:{type:254,value:0,tint:0}, fore:{type:255,value:0,tint:0}}`。

### 4.1 排错顺序

1. 先只写 `xf: { font: { bold: true } }` → 通说明 `format` 通道活着，问题在 `fill` 写法。
2. 再只写 `xf: { fill: { type: 1, back: {...tint:0}, fore: {...} } }`。
3. 还报错就换 `sheet.range_data_batch_update`，字段名要下划线 + 全称 `op_type: "cell_operation_type_format"`、`row_from/col_from`。

### 4.2 回读验证的局限

`get_range_data` 只能看到 `cell_background_color`，**看不出是实心还是斜纹**——斜纹和实心都返回 `#FFFFFF00`。所以颜色对不对必须靠肉眼看，或者对比同一行 A~E 是否视觉一致。

**范围大于 50 行时底色会失真**：部分格子返回默认的 `#FFFFFFFF`，实际是黄的。判「待入库」和验「涂没涂上」都要小范围读（≤10 行、只读 A/B 两列），详见 `踩坑记录.md` 第 15 条。

空单元格整条不返回，别把「缺列」当成「没涂」。一次 `rangeData` 塞 10 行比较稳，太多会超时。

### 4.3 批量重刷历史行

颜色写错过一次，历史行会集体变斜纹。补救就是**整段重刷**（幂等，不会叠加）：

1. 把 rowFrom/rowTo 连续的行拼成一个 `rangeData` 数组，每项 10 行以内；
2. 每批之间停 ~300ms；
3. 刷完抽查：`get_range_data` 确认行号对、`cell_background_color = #FFFFFF00`，再让用户看一眼有没有纹理；
4. 之前误刷出来的测试块用 `fill: {type:1, back:{type:254,value:0,tint:0}, fore:{type:255,value:0,tint:0}}` 清回无填充。

## 5. 验证

涂完回读同区域，确认 `cell_background_color` 变成 `#FFFFFF00`，并确认**相邻行仍是 `#FFFFFFFF`**，防止刷到别人。

`完整数`/`次品数` 为空的格子不会出现在回读结果里，属正常现象，看相邻有值的格子是否变黄即可。
