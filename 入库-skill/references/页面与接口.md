# 聚水潭售后扫描 · 页面结构与接口

> 实测环境：360 安全浏览器 16.x（内核 `Chrome/148.0.7778.218`，UA 含 `360SE`），CDP 9224。QQ 浏览器、Edge 结构一致。

## 1. 域名与 iframe 嵌套

入库账号登录后落到 `https://www.erp321.com/epaas`（注意不是 `dopre.jushuitan.com`）。这是 React SPA，查询走 XHR，不整页回发（`aspnet.viewstate=false`）。

嵌套关系：

```
www.erp321.com/epaas                      ← 顶层文档
 ├ iframe#iframe-welcome-page  [60,36,1812,923]   （欢迎页，可忽略）
 ├ iframe#iframe-556           [60,36,1812,923]   scanningv3.aspx
 │   └ iframe[name=AfterSaleScan] [0,0,1812,923]  erp-oms-aftersalescan  ← 真正的 UI
 ├ iframe#epaasDialogFrame     [0,0,1872,959]
 └ 若干 side-menu-iframe-*
```

**坐标换算：帧内 CSS 像素 + (60, 36) = 页面坐标。** dpr = 1，不需要再乘缩放。

确认帧偏移的方法：

```bash
node scripts/jst-scan.cjs eval epaas "JSON.stringify([...document.querySelectorAll('iframe')].map(f=>{const r=f.getBoundingClientRect();return {id:f.id,r:[r.left,r.top,r.width,r.height]}}))"
```

## 2. 关键控件（AfterSaleScan 帧内坐标）

| 控件 | 选择器 / 识别方式 | 帧内位置 |
|---|---|---|
| **主查询框** | `input.ant-input.ant-input-borderless` 里第一个，**无 id、无 placeholder** | `[157,22,186,39]` → 页面 (310,77) |
| 重置 | 按钮文字 `重置` | `[233,74,60,28]` |
| 查询 | 按钮文字 `查 询` | `[301,74,43,28]` |
| 商品编码/唯一码/国标码 | `input...canSpaceSend`（class 带哈希，别硬编码） | `[57,132,286,50]` |
| 售后信息·快递单号 | `#lId` | `[64,242,239,23]` |
| 售后信息·快递公司 | `#lcName` | `[64,281,239,23]` |
| 问题类型 | `#questionType`（ant-select） | `[64,318,260,26]` |
| 备注信息 | `#remark` | `[56,353,288,40]` |
| 本次数量 | `input.ant-input-number-input` 中 `x ≥ 1300`、无 placeholder 的那个，带 `−/＋` 步进器 | 约 `[1388,352,66,45]` |
| 次品 | 同级 `input.ant-input-number-input`，**placeholder 就是「次品」** | 约 `[1463,360,70,30]` |
| 确认收货 | `button` 文字含 `确认收货` | 页面约 (260,920) |

- 表格**不是** antd table，是 styled-components 的 `art-table`（`tr.art-table-row`、`td.art-table-cell`），所以 `tbody tr.ant-table-row` 查不到行。
- 单价输入框也在 `ant-input-number-input` 里（x≈1187，值形如 `29.9500`），**填数量时必须用 x ≥ 1300 过滤掉它**，否则会把单价改掉。
- 复选框 id：`confirmRefund`（收货确认退货单）、`confirmChange`、`bindOrder`、`openKeepLast`、`showBigImg`、`correctLcEnabled`、`quickReceiveWarehouseEnabled`。**不要动用户的勾选状态。**

## 3. 后端接口（预检用）

```
POST https://api.erp321.com/erp/webapi/afterSaleApi/scanning/search/v2
     ?owner_co_id=<公司id>&authorize_co_id=<授权公司id>
Content-Type: application/json; charset=utf-8
Accept: application/json

{"data":{"value":"<快递单号>","type":"l_id","isPromptMessage":false},"uid":"","coid":""}
```

- 两个 id 直接从扫描帧 URL 的 `location.search` 里取，**不要硬编码**（换工位/换账号会变）。
- 在扫描帧的上下文里 `fetch(..., {credentials:'include'})` 即可，**不需要** `gwfp` / `Webbox-Request-Id` 等头，浏览器带 cookie 就过。
- 单次约 197ms，并发 6 路稳定。

返回：

```json
{"code":0,"act":0,"data":{"list":[{
  "order":{"oId":ID-XXXX,"lId":"YT0721212385093","soId":"ORD-XXXX-XXXXXX",
           "shopName":"PDD-百顺婴童用品专营店","shopSite":"拼多多"},
  "afterSale":{"asId":ID-XXXX,"type":"普通退货","status":"WaitConfirm",
               "lId":"JT5548196989035","lcName":"极兔速递",
               "onlineStatus":"买家已经退货，等待卖家确认收货"},
  "items":[{"skuId":"XZ-XXL36","name":"小贝芯棉花糖纸尿裤XXL36",
            "qty":2,"currentQty":0,"defectiveQty":0,"type":"退货"}]
}]}}
```

要点：

- `code:0` 且 `data.list` 非空 = 有售后单可收。
- `code:ID-XXXX` = 该单号对应的售后单已全部入库或无明细，`msg` 里带售后单号。
- `data.list` **可能有多个元素**（一个快递单号对应多张售后单），`items` 里 `qty` 是申请数量，`currentQty` 是已收。
- `order.lId` 是**原发货单号**，`afterSale.lId` 才是退货面单号。换货件常出现「原单号不同、退货号能查到」。
- 判定「入过库没有」不要只看这个接口——`item` 全部收完后售后单仍会出现在 `list` 里（部分收货的情况），**唯一可信的判重依据是登记表涂黄**。

## 4. 界面回执（toast）

- 提交成功：`<单号> 退货成功`
- 已收完：`此快递单号对应的售后单:<asId> 已全部商品完成入库或者该售后单无退货商品明细…`
- 数量为 0：`收货的本次收货数量必须大于0`
- toast 容器：`.ant-message-notice-content` / `.ant-message-custom-content`，**存活约 3~5 秒**，必须在 1 秒内读。
- **确认收货没有二次确认弹窗**，点下去就提交，提交后页面自动复位（`#lId` 清空、本次总退数归 0）。
