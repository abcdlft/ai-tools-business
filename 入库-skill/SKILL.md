# 入库（聚水潭售后扫描 + 登记表涂黄）

## 用途

把「快递单号 → 聚水潭售后单 → 确认收货 → 登记表涂黄」这条链做成可批量执行的流水线。

核心提速点：**判断「这单能不能收」不走界面**。售后扫描页点一次查询要 1.9 秒，但它背后只有一个接口，在页面里用 `fetch` 带 cookie 直接调，单次 197ms，并发 6 路后平均 40ms/单。只有真正要收货的单才驱动界面。

## 何时使用

用户给出退货登记表要求入库；用户丢来一批快递单号要收货；用户问「这单入过库没」；用户要求把某些行涂黄。

## 前置条件（必须先确认，缺一不可）

1. **带调试口的浏览器已由用户双击启动**。启动器：`D:\log\浏览器\2-启动-360安全-9224.bat`（跨工位自适应，自动找浏览器安装位置）。不确定本机装了什么就先双击 `D:\log\浏览器\0-检查本机浏览器.bat`。AI 不能自己 `Start-Process` 拉起——命令一结束进程就被回收，必须用户双击。
2. 浏览器已登录聚水潭**入库账号**，当前标签在 `www.erp321.com/epaas`，打开的是「售后扫描」页（`erp-oms-aftersalescan`）。
3. 端口探活：`curl -s http://127.0.0.1:9224/json/version`，返回 `Chrome/...` 即通。

端口不是 9224 时用环境变量覆盖：`CDP_PORT=9225 node jst-run.cjs ...`。

> **9223 被乐言（智能助理 Nova，Electron）占用**。入库这条线固定用 9224，别改回 9223，否则两个程序抢端口、360 起不来调试口。

## 标准流程

### 1. 读表，找出待入库行

用 kdocs 连接器读登记表，**备注列为空 / 未涂黄**的行才是待入库。判重只看涂黄，不维护任何本地台账。

- 列顺序：`A 日期 | B 单号 | C 产品货号 | D 完整数 | E 破·脏·次品数量 | F 备注`
- 已涂黄 = `cell_background_color` 为 `#FFFFFF00`
- **判涂黄必须小范围读**（≤10 行、只读 A/B 两列）：一次读 50 行以上时接口会对部分格子返回默认白色，把已入库的行误判成待入库
- 表标识与读取要点见 `references/登记表与涂黄.md`

### 2. 批量预检

```bash
cd "<skill>/scripts"
node jst-run.cjs check 单号1 单号2 ...
```

输出每单：`✔ 单号 售后单数 申请数量 货号×数量`，或 `· 单号 售后单0`。

- `售后单0` = 聚水潭查不到该快递单号对应的售后单，**直接跳过，不要归因**。可能是换货件，也可能不在当前仓库账号下。不要下「客服没建单」这类结论。
- 结果同时写到系统临时目录的 `jst-last-check.json`（`os.tmpdir()`），需要时用 `node -e "console.log(require('os').tmpdir())"` 查路径。

### 3. 分流：机器能做的 / 交人工的

按 `references/判定规则.md` 执行。一句话版本：**机器只收「非 BBT + 非子母件 + 单售后单单行 + 表格总数等于聚水潭申请数 + 件数 ≤ 2」的单**，其余全部列清单交人工。

### 4. 收货

单笔：

```bash
node jst-run.cjs recv <单号> <入库数量> <次品数量> [--dry]
```

批量（一个进程跑完，别一条一条起进程）：

```bash
node jst-run.cjs run items.json
```

`items.json`：

```json
[{"row":8408,"no":"JT5549187962339","sku":"XZ-NB62","qty":2,"dqty":2}]
```

**每次先 `--dry` 演练**（只填不提交，返回 `filled` 和 `foot` 合计），确认数量对再真跑。真跑返回 `{"ok":true,"toast":"<单号> 退货成功"}`。

数量口径：`qty = 完整数 + 次品数`，`dqty = qty`（两框都填总数）。但**表格优先**——表格写 1 件、聚水潭申请 2 件时按表格填 1（部分收货）。

### 5. 涂黄

只对**收货成功**的行涂黄，A~E 五列，备注 F 不动。唯一正确写法：

```
xf: { type:1, fill:{ type:1, back:{type:2, value:ID-XXXX, tint:0}, fore:{type:255, value:0, tint:0} } }
```

三个必踩点（错了就是整片灰黄斜纹或 `Internal error`）：

1. `fill.type` 必须是 **1（实心）**；写 2 是图案填充，会变**灰黄斜纹**；
2. 颜色放 `back`，且 `tint` 必填（漏了报 `ID-XXXX Internal error`）；
3. `get_range_data` 回读**分不出斜纹和实心**，涂完要让用户扫一眼或截图确认无纹理。

完整调用样例、清空填充、排错顺序见 `references/登记表与涂黄.md`，坑位复盘见 `references/踩坑记录.md` 第 12~14 条。

### 6. 汇报

给用户一张表：行号 / 单号 / 货号 / 入库 / 次品 / 回执，外加「交人工清单」和「查不到的单」。

## 硬性红线

1. **没入库的绝对不涂黄**。收货失败、只演练没提交、交人工的单，一律保持白色。
2. **不动备注列 F**。
3. **不替用户改数量口径**。表格和聚水潭对不上时优先按表格，拿不准就问。
4. **BBT（卫生巾）一律不自动收**，包数换算交人工。
5. **子母件（`母DPK…` / `子DPK…`）一律不自动收**，交人工。
6. **一单一次确认收货**，不做「先收一半再补」的拆分，除非用户明说。
7. 收完必须验证：回执里要含该单号；必要时用 `check` 回查。
8. 涂完必须验收颜色：A~E 是**实心黄**、无斜纹；有纹理就整段重刷。

## 脚本

| 脚本 | 用途 |
|---|---|
| `scripts/jst-run.cjs` | 主力。`check` 批量预检、`recv` 单笔收货、`run` 批量收货 |
| `scripts/jst-scan.cjs` | 单步排查。`probe` 列控件、`state` 读快照、`js`/`jsaw` 在扫描帧执行、`shot --clip` 截图、`fill` 填单号查询 |

两个脚本自带 CDP 客户端，无 npm 依赖，`node` 直跑。
